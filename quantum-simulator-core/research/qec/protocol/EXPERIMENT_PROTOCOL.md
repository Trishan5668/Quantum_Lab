# Experiment protocol — static-DEM mismatch and calibrated candidate

**Pre-declared:** 2026-10-19, before confirmatory execution.  
**Machine-readable twin:** `protocol/static_dem_mismatch_v1.yaml`  
**Question:** see `RESEARCH_QUESTION.md`.  
**Phase 2 result used:** only to validate the execution stack; its seeds and
data are not reused as Phase 3 evidence.

## 1. Model and profiles

All simulations use Stim's rotated surface-code Z-memory:

```text
surface_code:rotated_memory_z
distance = d, rounds = d
after_clifford_depolarization        = p_gate
before_round_data_depolarization     = p_gate
after_reset_flip_probability         = p_gate
before_measure_flip_probability      = p_meas
```

The **oracle** decoder is built from the detector error model of the exact
circuit that generated the shots. The **nominal** decoder is built from a
circuit with all four hooks set to 0.010, regardless of the true profile.

| Profile | `p_gate` | `p_meas` | Role |
| --- | ---: | ---: | --- |
| `control` | 0.010 | 0.010 | Nominal model is correct |
| `measurement_heavy` | 0.002 | 0.020 | Measurement-dominated mismatch |
| `gate_heavy` | 0.020 | 0.002 | Gate-dominated mismatch |

Distances: 3 and 5. No other distances or profiles are added after seeing
results.

## 2. Paired design

For every `(profile, d)` cell, **one** detector/observable sample is drawn.
The same shots are decoded by:

1. nominal DEM,
2. oracle DEM,
3. calibrated candidate DEM (Phase 4 only).

Shots are therefore paired across decoders. Comparisons use exact McNemar on
discordant pairs and a paired bootstrap 95% interval for the risk difference
(10,000 resamples, seed derived from the cell seed). The bootstrap is a
descriptive interval, not a claim of exact coverage.

## 3. Phase 3 (limitation) design

- Confirmatory seed master: `3101`.
- Seed derivation: `SeedSequence([3101, distance, profile_code, 0])`.
- Shots per cell: **100,000**.
- Primary quantity:
  `relative_excess = (LER_nominal - LER_oracle) / LER_oracle`.
- Report absolute LERs, paired risk difference, relative excess, McNemar
  p-value, and interval. If `LER_oracle = 0`, report the zero-failure bound
  and mark the ratio undefined.

Pre-declared decisions:

- H3a supported if `relative_excess >= 0.10` at `measurement_heavy`, d=5.
- H3b supported if `relative_excess < 0.05` at `gate_heavy`, d=5.
- H3c supported if the d=5 excess exceeds the d=3 excess for
  `measurement_heavy`.
- If an interval includes the decision threshold, the result is
  **INCONCLUSIVE**, not rounded to support.

## 4. Phase 4 (candidate) design

### Candidate family

`calibrated_global_dem_v1`: a two-parameter global DEM with
`p_gate = p_reset = p_round` and `p_meas` chosen from a fixed grid:

```text
{0.001, 0.002, 0.004, 0.006, 0.008, 0.010, 0.012, 0.015, 0.020, 0.030}^2
```

### Candidate selection (development only)

- Development seed master: `4101`.
- Calibration shots: 5,000 per candidate cell and per true profile/d cell.
- Observed features: mean detector firing rate in each detector-time cohort
  (detector coordinate `t`), plus the overall mean.
- Score: mean absolute difference between observed and candidate-simulated
  cohort rates, normalized by the observed overall rate.
- Select the candidate with the minimum score. If the best two candidates are
  within 5% of each other in score, mark the selection **ambiguous** and fail
  the gate.

No held-out data enter selection. The true profile labels are not passed to
the selector; only observed detector statistics are used.

### Held-out evaluation

- Held-out seed master: `9101`.
- Shots per cell: 100,000.
- The candidate selected on development data is frozen before held-out
  sampling.
- The nominal and oracle decoders are re-run on the same held-out shots.

### Gates (all must pass)

| Gate | Criterion |
| --- | --- |
| G1 selection isolation | Candidate selected using development seeds only; code path records the master seed |
| G2 no control degradation | Control-profile candidate LER ≤ 1.02 × nominal LER, and paired interval excludes a >2% degradation |
| G3 recovery | On `measurement_heavy`, d=5, candidate recovers ≥50% of the oracle gain over nominal |
| G4 replication | The same direction of improvement is observed at d=3 and d=5 |
| G5 statistical evidence | McNemar p < 0.05 for candidate vs nominal on `measurement_heavy`, d=5 |

Outcomes: `PROMOTED` only if all gates pass; `REJECTED` if any fails;
`INCONCLUSIVE` if intervals cannot decide. A rejected candidate is retained
and is not tuned on held-out data.

## 5. AI-assistance policy

**No AI model or API was called for this study.** Candidate parameters are
generated by a deterministic rule-based grid search. The repository provides
a validated JSON schema for externally proposed candidates (source must be
labeled `EXTERNAL_AI`, `HUMAN`, or `RULE_BASED`), but no external candidate
was evaluated. Therefore:

- no “AI discovered” claim is made;
- no candidate is auto-promoted;
- an external candidate would still pass through G1–G5 unchanged;
- core experiments require no AI API.

## 6. Multiple comparisons and stopping

- Three profiles × two distances = 6 confirmatory cells, each with three
  decoder arms. All are reported.
- No early stopping and no optional stopping. Fixed shots.
- No multiplicity correction is applied; p-values are labeled descriptive
  unless a gate names a threshold. The gate thresholds are pre-declared.
- Failed or crashed runs are preserved with `failed-*` directories.

## 7. Artifacts

Each run records:

- exact circuits and DEM SHA-256 values,
- Stim/PyMatching versions,
- master seed and per-cell derived seeds,
- per-shot logical outcomes (packed bits),
- nominal/oracle/candidate failure vectors and comparisons,
- config hash, git revision and dirty status,
- manifest and SHA-256 checksums.

## 8. What would make this invalid

- Reusing Phase 2 seeds or data as Phase 3 evidence.
- Selecting the candidate on held-out data.
- Changing profiles, shots, seeds, or thresholds after looking at results.
- Reporting relative excess when the oracle LER is zero without a bound.
- Claiming a circuit-level native QuantumLab result (Stim is the executor).
- Claiming novelty for noise-aware decoding.

Any of these invalidates the run and must be recorded as a protocol deviation,
not silently corrected.
